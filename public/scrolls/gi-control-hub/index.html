2 · Voting & Approvals

The core problem this solves: one unvoted item stalls the whole workflow. The fix isn't a stricter deadline — it's not treating every decision the same way.

Three vote types, three different mechanics

Candidates
Highest stakes, lowest volume. A real person gets invited on camera — deserves a deliberate review with comments attached, not a swipe.
Topics
Highest volume, lowest stakes per item. A full 72h cycle per topic chokes the backlog — wants a lightweight continuous backlog instead (see §3).
Panels
Time-pressured — tied to a real shoot date. An unfilled seat 48h out is a different emergency than an undecided logo direction.

Risk-tiered, not one rule for everything

Reserve full 2-of-3 + 72h for what's genuinely hard to undo — equity, Third Rail topics, brand, panel format. Low-stakes items (most individual topics, minor creative calls) can run 1-of-3 fast-track or no objection in 24h = approved. The exact thresholds are an open call — see §6.

Killing the bottleneck

  • A personal queue, not a shared board. Each partner's first screen shows only what's blocking on them, specifically, and for how long.
  • Push the vote to them. One-tap approve/reject/defer via SMS or push (GHL already does SMS automation) — a vote that requires opening a dashboard mostly doesn't happen.
  • A standing weekly digest. "3 items waiting on you, blocking 2 episodes" sent on a fixed schedule, not something to remember to check.
  • Batch voting. Clear five pending items in under two minutes, swipe-style, instead of opening five separate screens.

Make it a feedback machine, not a chore

  • Reward speed, not volume. A streak indicator for voting within a set window — reinforces the one behavior that matters (the anchor metric is already "did we hit every date we promised," not episode count).
  • Visible momentum on items. A 2-of-3 progress ring on every open vote (the dashboard mockup's Approvals screen already half-draws this) makes a vote feel like something actively closing.
  • The decision log as a highlight reel, not just an audit trail — closing a vote should read like a small win.

3 · The Monday Call → Punch List

Not everything that comes out of the call is a vote. A decision needs partner agreement and flows into §2's voting queue. A task is already agreed, just needs doing — it skips voting entirely and goes straight onto the punch list.
Owner
One person, accountable for closing it. Sits in their personal queue — same mechanic as a blocking vote.
Followers
Visibility without ownership. Pinged on status changes (created / due soon / overdue / done); never sits in their action list.
Timer
A due date rendered as a live countdown, same green→amber→red urgency treatment as the vote clock — one visual language for urgency, not two.
Calendar
Sync out to Google Calendar — Erik already runs it day to day — rather than building a third calendar surface. The dashboard's own Calendar tab can mirror it.
The call's own shape

Four beats, every time: (1) review last week's punch list — closed / overdue. (2) run any votes ready to close. (3) capture new punch-list items and new topics live. (4) assign owner + due date + followers before anyone leaves the call.

7 · Open Decisions This Spec Surfaces

⚠ None of these are resolved here — they gate how the build actually starts
  1. Data architecture — the one that gates everything else. Build the hub as a real front-end on top of GHL's actual Creative Approvals pipeline via its API (keeps one system of record, matches the existing "GHL is the engine room" decision, needs GHL API access + likely a small serverless layer since a static Cloudflare Pages site can't hold API secrets client-side) — versus an independent data store (faster to stand up, fully custom, but becomes a second system of record next to GHL). Recommendation on record: keep GHL as the one source of truth.
  2. Risk-tier thresholds — which decisions get full 2-of-3 + 72h vs. 1-of-3 fast-track vs. silence-is-approval.
  3. On Location correspondent role — rotating partner or dedicated hire.
  4. E-sign tool — GHL's native Documents & Contracts vs. a dedicated third-party e-sign product.
  5. On Location cadence — runs independently weekly regardless of what the main panel show's own cadence vote lands on, or follows it.
